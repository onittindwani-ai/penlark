# Changelog

## 1.0.1 (2026-11-25)
- Hardening after a security review. The public demo password, the made up approver and viewer accounts, the demo buttons and the data reset now exist only while `DEMO_MODE` is on and no `OWNER_PASSWORD_HASH` is set. Setting the hash switches them off even if `DEMO_MODE` stays on, and the demo clock goes with them. The reset never erases the audit log and is refused on a server database. The API and the worker refuse an unsafe start (an example or short `SESSION_SECRET`, a demo on Postgres, the example `OWNER_EMAIL` with `MODE=live`) before the database is opened or anything is written.
- An approval is for the exact words. The approver now sees every character of a draft (it was the first 1,200), the approval keeps a fingerprint of the text, and deciding, planning on the calendar, exporting and sending are refused when the text changed. On Postgres the draft row is locked while it is edited or decided. An approval made before this release has no fingerprint: its draft cannot be exported until a second person approves it again. The API accepts a new approval request for such a draft; the Studio's Ask for approval button stays switched off while a draft shows as approved, so the request has to be made through the API until that is changed.
- Text that could freeze the app: banned patterns need an upper limit on every repeat and no repeat inside a repeat (refused when added, shown and skipped if already stored), the placeholder check and the markdown, transcript and X archive readers use bounded patterns, and uploads are read while they arrive (8 MB) off the main thread.
- Sign in: the email is compared without spaces or capitals for the limit and the lookup, with limits per address, per account and per address and account, field sizes are capped, and an unknown email costs the same work as a wrong password. The public click route uses the address uvicorn resolved, never the typed `X-Forwarded-For`; the web app passes on only the last address. The lead webhook and uploads are read in small pieces and refused as soon as they are too large, and a signature header with a strange character is a plain 401.
- Sending: a draft is claimed before the scheduling tool is called, so a second request cannot send it twice, and a draft saved at the scheduling tool is not sent again. A vendor refusal with a meaning (a 4xx answer) or a connection that never opened is said plainly, nothing is recorded as sent and the draft goes back (changed again below for an unclear answer). The kill switch set in the app now also stops the file export. A send no longer changes the shared adapter. Unknown platforms and dates are refused. The changes that were missing from the audit log (a rule deleted, an idea dropped, a plan removed, experiments, edits) are now recorded.
- A real install works end to end: add a voice from the app (Studio, Library and Voice profile pages) or with `python -m penlark.admin add-voice`, the built in banned phrases are saved on every start, and the owner, the timezone (`TIMEZONE`) and the allowed link hosts are settings. A tracked link host in `REDIRECT_ALLOW_HOSTS` now means exactly that host (write `*.example.com` for subdomains), and an empty list allows nothing outside the demo. Every setting is in `.env.example` and `docs/04-ENVIRONMENT-VARIABLES.md`, and a test fails when they drift apart. The API, worker, database migration and admin commands read the same settings file (`ENV_FILE`), and the demo data folder is found through `SEED_DIR` first, so an installed copy starts.
- Deploy: the Caddy API host serves only the lead webhook and `/health`; the Hetzner backup is private to its owner, keeps the exports folder and refuses an empty dump; the server installs Docker from Ubuntu's own packages. Docs say plainly what was and was not run (the workflow builds the images and starts the stack on GitHub; no real host was used).
- Web: an error page with a retry button, a form to add the first voice, and the approval page shows the whole draft.
- Second review (round 2). Find ideas no longer grows with the square of a long note: a test with four long notes held 300 MB, and ten notes of 15,000 characters took 3 GB, so a long call transcript could stop the API. The finder now keeps the 30 rarest words of each note, reads the newest 1,000 notes and 1 million characters, and on a real install runs in the worker (the button queues one job, shows its status and says when the worker is not running; the offline demo still answers at once). The worker is now needed on a real install.
- The claims check matches whole figures: `5 percent` is no longer sourced by a note that says `15 percent` or `1500`, and `15%` equals `15 percent`.
- Building a voice profile from 300 posts took 60 seconds of processor time; it now takes under a second (running means, one pass over the words), reads at most the newest 500 samples and 1.5 million characters, and a file with the same text twice adds it once.
- A save is finished before the answer is sent (every route), so a failed save is an error and no longer a success message. On SQLite a request that can write takes the write lock first, so four people saving at once cannot fork the audit chain and raise a false tamper warning; reads are never held up. The worker does the same.
- A send whose outcome is unclear (a timeout, a server error, an unreadable answer) leaves the draft in "send unclear", with no second send, edit or export, until a person presses It was posted or It was not posted in the Studio. A 4xx answer or a connection that never opened still puts the draft back to approved. Changed test: the one that expected a draft back at approved after a 500.
- The Docker image and compose file set `DEMO_MODE=false`, so a container with no variables refuses to start instead of being a public demo. The web app never reads `SESSION_SECRET`, so the Vercel guide no longer asks for it.
- `ALLOW_PRIVATE_SCHEDULER` (off by default) allows a Postiz on plain http or a private address. The scheduling tool's host is now looked up at the moment of each call, not at start, so a name server hiccup no longer stops the API and worker from starting.
- `LLM_BUDGET_USD` with a model that has no known price now stops the start (the base counted such a model as free). `ANTHROPIC_BASE_URL` is judged by its host, so `http://localhost.evil.net` is refused.
- Smaller: the link guard refuses backslashes, spaces and userinfo in a link; ids are limited to the database range and a note list to 500; `inf`, `1e999` and huge counts in a post numbers file are reported by row; vendor keys, hashes and the webhook secret stay out of the settings text, and a too short `SESSION_SECRET` is no longer printed in the start up error; `reportlab` and `pillow` are no longer installed (nothing used them) and `cryptography` is declared as pypdf's crypto extra; a SQLite file older than the code stops the start with a plain message.
- Tests: new tests for every fix. Nothing that tested a safe behaviour was removed. Three existing tests changed because they encoded the old behaviour: the one that expected a draft back at approved after a vendor 500 (now held as send unclear, with a new test for a 4xx), the real install walk through (Find ideas now goes through the worker), and the list of job handlers (now learn and ideas).
- Third review, sending. A post that was sent can no longer be taken off the calendar: only a planned item can (a sent or exported row is the record that stops a second send, and removing it put the draft back to approved so a second click posted it twice). A scheduling tool that answers with a success status but no post id (Postiz with an error body or an empty list, Buffer with an `errors` list, Metricool with an `error`) no longer counts as scheduled: the draft is held as "send unclear" with what the tool said, and a person says whether it was posted. A send writes a "being sent" calendar row when it starts; a send left behind for over 30 minutes is held as "send unclear" instead of being released to approved. Planning, moving and taking an item off the calendar hold the draft row like every other change.
- Third review, the database. A send to a scheduling tool, a model call (voice guide, draft variants, extra ideas) and the idea finder no longer hold the SQLite write lock while they wait: the lock is let go first and taken again for the result, and a model call writes its cost in its own short transaction. The lead webhook and the file upload no longer block the server while they wait for the database. Adding samples reads the library in batches. One lead or customer event counts once even when two arrive together (a unique index; `alembic upgrade head` on Postgres, at start on SQLite, repeated events removed).
- Third review, links and removing things. The draft link check reads an address the way a browser does: a backslash or a user name in front of the host is always foreign, and so are bare addresses (`evil.com/free`) and shortened links (`bit.ly/x`). The owner can delete a note, a sample, a draft, a voice and imported post numbers for good through the API, with the copies of their words the app made (ideas quoted from a note, profile versions built after a sample, variants, calendar rows and the exported file of a draft); sent drafts stay. The Library's Remove button now does that and is for the owner.
- Third review, smaller things. A CSV cell over 128 KB, an X archive with a text that is not text, a NUL character in any text, an outcome id over 120 characters, a tracked address too long once encoded, and an email address over 80 characters (refused at start) now give a plain message instead of an error page. A PDF has a text and time budget. The text of the settings no longer prints the database address. The web proxy refuses a path segment holding a question mark, hash, semicolon or space. A tracked link that hits the click limit says so (429) instead of "this link does not exist", and the settings page warns when requests come through a proxy that `FORWARDED_ALLOW_IPS` does not list. The flags in the draft editor land on the right words when the text holds emoji. The web app sends a Content-Security-Policy. The tools start the project's own Python by themselves (`python3 tools/doctor.py` works on a fresh clone after `make install`), and `tools/check_docs.py` now checks data/counts.json against the files, with `tools/check_counts.py` for the test count. The API description in `pyproject.toml` and the exact counts in two tests are corrected.
- Fourth review. Text that only looks like a link no longer stops the app: `https://[YOUR LINK]`, `https://[abc` or an address followed by full width punctuation (common in Chinese, Japanese and Korean writing) made the link check raise an error, so the draft could not be opened, matched, sent for approval or approved. Such text is now flagged as not yours, the tracked link maker answers 422, a stored target that cannot be read answers 410, and full width letters, dots and slashes are read the way a browser reads them. The bare address check no longer skips an ending written in capitals (`EVIL.COM`, `Evil.Com/x`), a domain in another script (`пример.рф`, `bücher.de`) or an ending that was missing from the list (`.zip`, `.tk`, `.cam`, `.rest`, and about 250 more); any `word.word/path` is flagged, and only a capitalised sentence word after a full stop (`Done.It works`) is skipped.
- Deleting a note now takes every copy of its words the app made: the title of an idea that is kept is made again from the evidence that is left, the titles of the drafts made from it (and their approval requests) are cleared, and the variants that quote it are removed (a variant that is the draft's own text stays and the draft is listed). Deleting a sample does the same for variants and titles that quote its sentences. The answer gives `titles_cleared`, `variants_removed` and `drafts_still_quoting_it`.
- Smaller: the live match and the profile comparison no longer take the SQLite write lock; a NUL character in an approval note or a comparison text is taken out; the web proxy no longer follows a redirect and refuses the `public` tree (a tracked link opens only through `/r/<code>`); a send for a chosen day goes out at the new `SEND_HOUR` in `TIMEZONE` (default 9) instead of midnight UTC, a date in the past is refused, a date with Buffer is refused because Penlark cannot give Buffer a time; a second send while the first is still out no longer deletes the first one's calendar row; "It was posted" keeps the platform of the send; the docs run `python -m penlark.admin` from `.venv`. Documented and not changed: the slow import of a very large post numbers file, a hand edited guide lost with a deleted sample, repeated version numbers, click counts that can be inflated by changing the browser name (`docs/14`).
- Tests: `apps/api/tests/test_round6_audit.py`, each test failed before its fix. Nothing that tested a safe behaviour was removed or weakened.

## Earlier changes in 1.0.0 (round 5, a walk through every screen)
- A draft that was edited after it was sent for approval can no longer be approved: the edit withdraws the request (shown under Decided with its reason), and approving checks the draft and the house rules again. The demo draft that waits for a second person has finished text, no brackets.
- The voice you pick in the Studio is saved with the draft. Unsaved changes are shown and asked about before another draft opens. A viewer sees the draft read only and every write control switched off with a reason.
- Duplicates are refused with a reason: the same banned phrase, the same writing sample (pasted or in a file), the same post numbers imported twice, the same tracked link made twice. Empty files, a stray word and unsupported file types are refused as samples.
- Exporting a planned draft keeps one calendar entry on its planned day and platform. The Studio can copy the text.
- Phone top bar keeps Pause all and Sign out; the kill switch button and banner say what it stops; the palette runs actions (theme, sign out, kill switch, run, clock, reset); G then a number goes to a page; sign in returns to the page that was asked for.
- Tables line up their columns with their headers on every row; row buttons show on touch screens; tables whose rows open nothing no longer say enter opens. Files dropped on the Library or the CSV import go to a drop zone, a drop anywhere else no longer makes the browser leave the app.
- Plain words for the audit log (with a detail sheet), the integrations page (no raw category names) and the calendar week. Short links show the address the app is open on.

## Earlier changes in 1.0.0 (round 4, part M)
- Model path for the voice guide, draft variants and idea finder (`model_tasks.py`), selected by `LLM_BACKEND` plus `GUIDE_WRITER`, `DRAFT_WRITER`, `IDEA_FINDER`. Code re scores every model draft, a model cannot approve or schedule, live use UNVERIFIED. Local fake server and recorded fixtures.
- The approval request now refuses a draft under the minimum voice match.
- Banned phrases match hyphens, curly apostrophes and word endings; 34 more stock phrases; narrower client claims, number words as figures, more experience verbs; better stemmer for the idea finder.
- Independent held out sets A and B, scorer `tools/eval_independent.py`, `docs/INDEPENDENT-EVAL.md`.
- Contract tests for the scheduler adapters against published descriptions (Postiz OpenAPI; Metricool and Buffer partly). `tools/doctor.py` repaired.

## Earlier changes in 1.0.0 (first rounds)

- Renamed from Voiceprint to Penlark after a public name check. The Python package, environment variable prefix, interface text, documents, prompts, templates and screenshots all use the new name.
- Read only sign in: `VIEWER_EMAIL` and `VIEWER_PASSWORD_HASH` (demo `viewer@example.test`). It opens every page and changes nothing.
- Approvals are decided by the base rule: the person who asked cannot decide. The route's own check is removed.
- `LLM_BACKEND` (offline, fixture, anthropic) replaces `LLM_MODE`. The offline template writer sits behind the same request shape a model will use (`offline_llm.py`). The model writer itself is still to come.
- `LOGIN_BURST` setting for the sign in limit (default 5; the browser tests raise it).
- Posting rhythm: `CADENCE` (default `linkedin:2,x:2`), `GET /api/cadence`, and a rhythm strip and platform picker on the Calendar. A plan and a nudge, never a block.
- Decided defaults replace the founder fact tags: reading level grade 9 or lower (was 12; a text under 8 words is not judged on reading level), dashes banned in marketing text and configurable, voice match 60, tracked link hosts as an allow list the implementer sets.
- Guide 10 is `10-USING-IT-FOR-A-CLIENT.md` (what to charge for, onboarding, handover, contract points).
