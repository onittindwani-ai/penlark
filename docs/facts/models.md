# Language model path

UNVERIFIED live. Date written: 2026-11-23.

What the code does (`apps/api/src/penlark/model_tasks.py`): it goes through the base wrapper (`sendora_core.llm`), which sends `POST /v1/messages` to the Anthropic Messages API with the key in `x-api-key`, the `anthropic-version` header, a system prompt, the data blocks (profile, writing samples, guide, evidence quotes, notes) each inside a marked untrusted block, and a JSON schema in `output_config.format`. The request and response fields follow the vendor documentation as read for the base on 2026-11-23 (see the hub's facts file). Model: `claude-sonnet-5-5` for all three jobs.

Three jobs: write the plain language voice guide (from the measured numbers and four short excerpts), write draft variants of a post, script, email or newsletter (from the locked guide and the idea's evidence quotes), and find ideas that recur across different notes (each with verbatim quotes).

What code does around the model (all tested against a mock server): sentences of the notes, samples and quotes that give orders are never sent, marker lookalikes cannot close a data block, and a favourite word that came from such a sentence is left out of the profile; every answer must match a fixed schema with no extra fields, so a model cannot set a status, an approval or a score; **code re scores every variant a model writes** (voice match against the locked profile, house rules, claims check, brackets) and writes the numbers on the variant, flagged NEEDS WORK when it fails; a variant that gives orders, says something was sent or published, or holds a link that is not in the evidence is dropped; a guide with a link, orders or no content is replaced by the plain rules guide and dashes are removed; every idea quote is found again by code in its note and replaced by the note's own characters, an idea needs verified quotes from two different notes, and its score is computed by code; a bad answer, a kill switch or a spent budget falls back to the plain code. The module imports no approval, scheduling or adapter code (a test reads its imports), and the approval request itself refuses a draft under the minimum voice match.

What was run: the whole path against a mock server on this machine (`mock/anthropic_mock.py`) that checks the request shape, and replay of recorded answers (`data/llm_fixtures/`, made by that mock server, not by a real model). **Never run with a real key.** How a real model writes in a real person's voice, its cost and its error rate are unknown. A test also proves that with `LLM_BACKEND` unset no connection is made even when a key is in the environment.

Switches: `LLM_BACKEND` (offline, fixture, anthropic), `GUIDE_WRITER` and `DRAFT_WRITER` (model by default, effective only when a model backend is on), `IDEA_FINDER` (rules by default). See `04-ENVIRONMENT-VARIABLES.md`.
